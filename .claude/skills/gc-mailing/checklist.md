# Чек-лист рассылки GetCourse перед отправкой

Проходить сверху вниз. Любой «нет» — исправить до нажатия «Готово к отправке».

## 1. Название и теги
- [ ] Название по формату: канал, продукт / событие, дата, время отправки (`[EMAIL] … [23.10.26] в 8`).
- [ ] Время в названии совпадает с полем «Когда отправлять».
- [ ] Теги (action-…, событие, продукт) стоят — по ним потом ищут статистику.

## 2. Тема, прехедер, HEAD
- [ ] Тема как в ТЗ, без опечаток, `{first_name}` написан именно так (фигурные скобки, латиница).
- [ ] В «HEAD письма» есть `<vk-snippet-end/>` — в превью почтовика виден только прехедер.

## 3. Текст письма
- [ ] Текст сверен с ТЗ: ничего не потеряно, не добавлено, порядок абзацев тот же.

## 4. Ссылки и кнопки
- [ ] Каждую кнопку и ссылку в тексте открыть по клику — страница живая, без 404 и без «доступ запрещён».
- [ ] Ссылка ведёт на страницу ЭТОГО события / даты, а не на прошлую (проверить дату в адресе).
- [ ] UTM-метки есть и соответствуют письму (source / campaign / content — дата, канал).

## 5. Картинки
- [ ] Баннер добавлен отдельным блоком.
- [ ] Баннер нужный (дата, спикер, продукт), не от прошлой рассылки.
- [ ] У картинок есть alt-текст; если картинка ведёт по ссылке — ссылка верная.

## 6. Получатели
- [ ] «Кому отправлять» — сегмент, а не «Всей базе» / «Никому» по ошибке.
- [ ] Условия сегмента читаются правильно: «и/или», галочки «не», нужное предложение/группа с нужной датой.
- [ ] В условиях сегмента выбран тип «ученик».
- [ ] Боты: в условия добавлено «Подключен бот»; для ВК — ещё «Можно отправлять ВК сообщение».
- [ ] Число получателей правдоподобное (кнопка подсчёта / просмотр выборки).
- [ ] «Рассылать по»: нужный режим (обычно «По адресам, которые заведомо существуют»).

## 7. Финальная проверка
- [ ] «Анализ текста» запущен, предупреждения просмотрены.
- [ ] Тестовое письмо себе — открыто на телефоне и компьютере (Gmail + Яндекс/Mail.ru): вёрстка, картинки, имя, кнопки кликаются.
