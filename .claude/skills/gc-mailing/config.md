## Название рассылки (обязательный формат)
`[КАНАЛ] [<акция>-<дата эфира ДД.ММ.ГГ>] <Эксперт> / <Продукт> / <ДД ММ в ЧЧ>[ (следом)]`
- КАНАЛ: `ПОЧТА`, `ТГ`, `ВК`, `МАХ`
- пример: `[ПОЧТА] [ОВ2-8.10.26] Е.Станковская / Терапия сценариев / 10 10 в 10`
- `(следом)` — второе сообщение бота, которое уходит сразу за первым
- Теги образца: `action-ОВ2`, `expert-Елена Станковская`, `project-терапия сценариев`, `воронка` — при копировании сохраняются; если акция другая — спросить теги.
- Вход: пользователь сам входит в GC в Chrome. Если открылась страница входа — остановиться и попросить войти.

## Что делает пользователь сам (агент НЕ трогает)

- **Дата/время отправки** и запуск («Готово к отправке»).

## Заметки по интерфейсу GC
(агент дописывает сюда то, что выяснил на прогонах: селекторы, порядок экранов, ловушки)

- Страница рассылки: `/notifications/control/mailings/update/id/<ID>` — вкладки `part/main`, `part/settings`, `part/test`. На странице есть кнопка **«Копировать»**.
- Получатели: радио `ParamsObject[recipients_type]` (Никому / Всей базе / Сегмент), сегмент `Mailing[segment_id]` или произвольные условия. В образцах — произвольный сегмент из условий. При копировании условия копируются — так и оставлять (просьба пользователя 13.10.2026).
  Условия сегмента лежат в скрытом поле `rule` (JSON), которое JS дорисовывает на ОТКРЫТОЙ странице — при `fetch`+`DOMParser` его нет. Поэтому: при POST формы, собранной через fetch, обязательно передавать `rule` (взять с отрисованной страницы этой же рассылки или образца), иначе условия сбросятся и останется «Сегмент» без условий (опасно — может уйти всем). Проверять `rule` на открытой странице.
- Расписание: `Mailing[schedule_type]` (По готовности / В указанное время), `Mailing[need_send_at]` формат `2026-10-10 10:00:00`. Не выставлять.
- Галочка «Отправлять в приложение» (`ParamsObject[send_to_chatium]`) в образце письма включена.
- **E-mail собран в блочном конструкторе GC** (не HTML): `.notification-message-content .builder-item.part-mailing-{image|text|button}`. Тема — в `.panel-heading` блока сообщения.
  Структура образца: баннер (image) → текст → кнопка → текст → кнопки (по одной на блок) → картинка → подвал (подпись «С заботой, команда Life Practic», контакты lifepractic@gmail.com, «Полезные ресурсы», life-practic.ru, соцсети, картинка). Подвал не трогать.
- В тексте GC используется `{first_name}` как есть — заменять не нужно.
- **Боты (ТГ/ВК/МАХ)**: простой текст, пустая строка между абзацами, списки — через `🔹` в начале строки (вместо «-»), кнопки — штатные кнопки сообщения бота. Тексты ТГ/ВК/МАХ одинаковые. Длинное письмо делится на 2 рассылки: первая (с картинкой) + «(следом)».
- Отправленные рассылки (статус «Завершена») — только читать.

### Рецепт e-mail (проверен 13.10.2026 на рассылке 23267245)
1. Образец → кнопка «Копировать» внизу справа (НЕ «Сделать черновиком» — это меняет сам образец). В окне: «Новое название» (Cmd+A + `type`), транспорт → зелёная «Копировать». Открывается копия (статус — черновик, есть кнопка «Готово к отправке» — НИКОГДА не нажимать).
2. В копии сразу: `Mailing[subject]`, `Mailing[preHeader]` (focus+select через JS, ввод через `type`), `schedule_type=from_mission` (получателей не трогать) (копия наследует старую дату `need_send_at`) → синяя «Сохранить» → должно появиться «Рассылка сохранена».
3. «Редактировать» → `/pl/notifications/control/mailings/editor?id=<ID>`. Текстовые блоки — Redactor 3 (`.redactor-in`), `$R` недоступен, синтетический paste игнорируется.
   Работает: реальный клик по блоку → JS: выделить всё в `.redactor-in` + `document.execCommand('insertHTML', false, html)` → удалить пустые `<p></p>` → `type` " " + `BackSpace` (иначе конструктор не забирает изменения) → клик по пустому полю справа (x≈1300) → «Сохранить» вверху. Сохранение перезагружает страницу (JS-переменные пропадают).
   HTML как в образце: `<p>`, `<ul><li><p>…</p></li></ul>`, `<strong>`, `&nbsp;` после предлогов/союзов и перед «—». Генератор: `md2gc.py` в этой папке.
4. Иконки блока появляются по hover: `.copy-item-handler` (дублировать — копия встаёт сразу под блоком), `.sort-item-handler` (перетаскивание — мышью НЕ работает), `.delete-item-link`, `.setting-edit-link` (шестерёнка).
   Переставить блок: найти `.ui-sortable` (`.builder`), переместить DOM-узел верхнего уровня (`b.after(a)`) и вызвать `jQuery(bld).sortable('instance').options.stop.call(bld, jQuery.Event('sortstop'), {item: jQuery(a)})` → сохранить.
   Стрелки ↑↓ в правой панели двигают всю секцию, не блок.
5. Кнопка: шестерёнка → панель «Элемент»: «Надпись на кнопке», «Ссылка» → «Сохранить и закрыть».
6. **Типограф GC** на каждом текстовом блоке: реальный клик по блоку + клик в текст → JS: `ed.focus()` и на `.re-typograph` отправить `mousedown`, `mouseup`, `click` (обычный `.click()` не срабатывает; кнопка панели может быть за экраном — это не мешает). Типограф работает в браузере, без запросов к серверу. Потом `End` → пробел → `BackSpace` → клик мимо → «Сохранить». На письме 15/10 он добавил только неразрывные пробелы в «15 лет», «7 дней», «3 лекции» (это правило уже есть в `md2gc.py`).
7. Самопроверка: SHA-256 нормализованного `innerText` блоков (nbsp→пробел, пробелы схлопнуть) против текста документа без разметки. Делать ПОСЛЕ типографа — он не должен менять слова.
8. **«Анализ текста»** на странице рассылки (кнопка под темой, справа) → переписать предупреждения в отчёт. Постоянные пункты Life Practic, на которые не реагировать: стоп-слова (цена, Свобода, работа, скидка, подарок — это суть писем), ссылки на life-practic.ru и t.me и иконки соцсетей без alt (всё это подвал из общего шаблона рассылок, правится в шаблоне, а не в письме), нет телефона отправителя (тоже подвал).
   Слова НЕ менять. Русские буквы на латинские (a, e, o…) НЕ подменять никогда: почтовики считают смешанные алфавиты признаком фишинга.

### Пакетный режим через запросы (проверен 13.10.2026, ОВ3: 34 бота + 11 ТГ ДГК)
- Копия: GET+POST `/notifications/control/mailings/duplicate/id/<образец>` (форма: `Mailing[title]`, `Mailing[transport]`, `save=1`); id новой рассылки — из `response.url`. Теги при этом НЕ копируются.
- Сохранение: GET страницы рассылки → `new FormData(form)` (кнопка `ready` = «Готово к отправке» в FormData не попадает, НИКОГДА её не добавлять) → заменить `Mailing[content]` / `Mailing[subject]` / `Mailing[preHeader]`, `Mailing[schedule_type]=from_mission` (получателей НЕ менять) → POST на `form.action` как urlencoded → перечитать и сверить.
- Старое вложение бота удалить: `FileList[files][<файл>][for_delete]=1`.
- Данные в страницу: файл через `file_upload` в `<input type=file>` на `/robots.txt` того же домена → `localStorage` (хранилище своё у каждого домена).
- Ссылки в кнопках: брать из образца по подписи кнопки (пользователь просит ссылки не удалять).
- Боты: делить на две рассылки («… » + «… (следом)») ТОЛЬКО там, где в документе стоит фраза «следующим сообщением» — по ней и резать. Нет фразы → одно сообщение, самой по лимиту 1024 не делить.
- Если во вкладке «Бот» нет текста письма — брать текст из «Емейл» без «Здравствуйте» и сказать об этом пользователю.
- Правка уже созданной рассылки: менять ТОЛЬКО `Mailing[content]`, ссылки сохранять из текущего содержимого по подписи кнопки (пользователь мог вставить свои), получателей/время/картинки не трогать.
- Почта (конструктор) требует ВИДИМОЙ вкладки: в скрытой вкладке таймеры заморожены, Redactor не стартует от программного клика. Блоки: удаление/копирование — JS `.click()` по `.delete-item-link` / `.copy-item-handler` (`window.confirm=()=>true`), порядок — `sortable('instance').options.stop`, кнопки — панель `.popover.setting-editor-popover` (сначала mouseover на блоке). Текст — `jQuery(.f-text).data('redactor')` = Redactor II: после активации блока `R.code.set(html)` + `R.code.syncFire(R.code.get())`.
- Почта: между абзацами `<p><br></p>` (иначе слитно) — `md2gc.py` делает это сам.
- ДГК = аккаунт psyclassfze.com (ТГ-образец 23271639, почта-образец 23271470), каналы: EMAIL + ТГ.

### Картинки (проверено 19.10.2026)
- Баннеры из Google Drive: `download_file_content` (с разрешения пользователя) → base64 → файл; сжать `sips -s format jpeg -s formatOptions 85 -Z 1200`.
- Загрузка в файловое хранилище GC: на странице ТГ-рассылки есть два uploadifive-поля; рабочее — БЕЗ имени, рядом со скрытым `FileList[add_telegram_files]`. Перенести его в начало `body` (`aria-label`), найти через `read_page` (filter interactive, max_chars 300) и отдать файл `file_upload`. Ответ — код файла `<hash>.jpg` в скрытом поле. Прямой `fetch` на uploadScript даёт 404. ОДИН файл на одну загрузку страницы: второй файл в то же поле встаёт в очередь и не грузится — перезагрузить страницу, снова перенести поле (ref обычно тот же `ref_1`). Ждать хеш через `setTimeout`, не через MessageChannel-цикл (он вешает вкладку).
- Файл по коду: `/pl/fileservice/user/file/download/h/<hash>`.
- Почта: в панели блока картинки поле `[inner][image][hash]` = код файла, `[inner][alt]` = описание → «Сохранить и закрыть» → «Сохранить».
- Боты (ТГ/ВК/МАХ): POST формы с `FileList[add_files]=<hash>` (НЕ `add_telegram_files` / `add_max_files` — на них 500) + `rule`. В ТГ потом второй POST (свежий GET формы `#yw0`, `save=1`, `rule`) с `FileList[files][<hash>][attach_type]=photo` (иначе тип пустой). Форма ботов — `#yw0` (поля `Mailing[title]` в ней нет). ВК сохраняется медленно: fetch с таймаутом 40 с, при повторе проверять, есть ли уже хеш в странице, чтобы не прикрепить дважды. МАХ ставит `image` сам, в ВК выбора нет.
- Эмодзи 🤍 (U+1F90D), 🧩 (U+1F9E9) и 🤩 (U+1F929) GC при сохранении бот-текста превращает в ⭐ — передавать кодом (`&#x1F90D;`, `&#x1F9E9;`). Похоже, так со всеми «новыми» эмодзи (Unicode 11+): после сохранения сверять текст, расхождение в первом символе = эмодзи заменился.
- В ПОЧТЕ (конструктор) 🤍 тоже становится ⭐ при сборке письма, и обойти это не удалось (ни кодом `&#x1F90D;`, ни через `updateBlockParam`). Предупреждать пользователя. 🎉 🎁 🔥 ✅ сохраняются нормально.
- Бот-сообщение с картинкой: подпись в Telegram — максимум 1024 знака. Если текст длиннее, а «следующим сообщением» в ТЗ нет, предупредить пользователя.

### Рецепт ботов ТГ / ВК / МАХ (проверен 13.10.2026: 23267697/662, 23267718/712, 23267732/725)
1. Текст брать из вкладки «Бот» (он короче e-mail — не путать). Делить на 2 рассылки: первая (под картинку) — заголовок + вводные абзацы до «Вы узнаете, как:» (≤1024 знаков), вторая «(следом)» — остальное + кнопки.
2. Копировать образец «(следом)» своего канала (ТГ 23198403, ВК 23198402, МАХ 23198405) ДВА раза: «… / ДД ММ в ЧЧ» и «… / ДД ММ в ЧЧ (следом)».
   Копирование скриптом: `button` «Копировать» вне `.modal` → `.click()`; в модалке `input.value = название`; кнопка подтверждения — это `a.btn.btn-success` (НЕ `button`) → `.click()` через `setTimeout`. Переход на копию идёт 3–7 с — ждать, не нажимать повторно (иначе дубль).
3. Текст: Summernote, `jQuery('[name="Mailing[content]"]').summernote('code', html)` — синхронизирует textarea сразу. Генератор: `bot2gc.py` (`<p>`, 🔹 вместо «-», `<b>`, кнопки — `<p><a href="">Текст</a></p>` в конце, галочка `asButton` в копии уже стоит).
   **Пустая строка:** ТГ и МАХ — `<p>&nbsp;</p>`; **ВК — только `<p><br></p>`** (ВК-редактор выкидывает `&nbsp;`-абзацы, текст слипается).
   Ссылку «Связаться с менеджером» взять из старого содержимого копии (без utm); остальные `href=""`.
4. Радио `schedule_type=from_mission` (получателей не трогать) → `button` «Сохранить» `.click()` → «Рассылка сохранена».
5. Проверка всех копий одним скриптом: `fetch('/notifications/control/mailings/update/id/<ID>')` + `DOMParser` → textarea → `p.textContent` через пробел → SHA-256 против текста документа.
- Координаты кнопки «Сохранить» вверху редактора каждый раз брать из DOM — размер окна меняется, и кнопка сдвигается. Признак успешного сохранения — перезагрузка страницы (JS-переменные пропадают).

### Теги рассылки (проверено 20.10.2026)
- Теги — виджет `.gc-tags` в шапке страницы рассылки (`data-tags`, вне формы `#yw0`; POST формы их не меняет). Текущие теги читать из `data-tags` в HTML страницы (fetch).
- Менять: открыть страницу → `jQuery('.gc-tags').trigger('click')` → дождаться видимого `input.tag-editor-hidden-src` и загрузки списка тегов (`.gc-tag` ≥ 20, иначе ошибка filterTags) → `jQuery(input).tagEditor('removeTag'|'addTag', name)` → зелёная «Сохранить» (`button.btn-success`) → проверить `data-tags` повторным fetch. Крестик закрывает БЕЗ сохранения. Клики по списку тегов мышью промахиваются (список перестраивается) — только через API.

### Разбор документов (с 22.10.2026)
- ТЗ брать HTML-выгрузкой (`download_file_content`, `exportMimeType: text/html`) → `python3 -I gdoc_items.py <tool-result> <dir>` (жирный, курсив, жёлтая заливка = кнопки/служебное, комментарии отдельно) → spec.json с номерами абзацев → `python3 -I items2emails.py items.json spec.json emails.json` (формат ov3_emails).

- Ответ меньше лимита приходит прямо в чат и не сохраняется в файл (дорого и не обработать скриптом) — большие документы качать HTML, маленькие проверять `read_file_content`.

### Чтение ТЗ через Chrome при недоступном Drive-коннекторе (13.11.2026)
- `fetch('/document/d/<ID>/export?format=html')` в новой вкладке docs.google.com (в старой вкладке таблицы фриз). Форматирование в выгрузке — через CSS-классы (`.cN{font-weight:700…}`), а не inline: разбирать `<style>` → классы. Парсить indexOf-сканером (регулярка с `[\s\S]*?` на 1 МБ вешает вкладку). Результат в виде runs-JSON передавать на диск: textarea на странице → реальный клик + `cmd+a cmd+c` (computer) → `LC_ALL=en_US.UTF-8 pbpaste > file`. `fetch` на localhost из docs блокируется, вывод javascript_tool режется ~1000 знаков.
- 🧭 (U+1F9ED) в письме (конструктор) превращается в ⭐ так же, как 🧩/🤍/🤩 — предупреждать.
- Загрузка картинки скриптом (13.11.2026): на странице ТГ-рассылки безымянный `input[type=file]` принимает `File` из canvas (`DataTransfer` + событие `change`) — хеш появляется в `FileList[add_telegram_files]`; картинка по `…/pl/fileservice/user/file/download/h/<hash>.jpg` грузится как `<img>` (fetch с CORS не проходит). Страницу рассылки после этого НЕ сохранять.
