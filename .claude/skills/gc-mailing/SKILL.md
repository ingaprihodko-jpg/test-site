# Агент рассылок GetCourse

Задача: взять письма из Google Docs и создать **черновики** рассылок в GetCourse.
Текст не пишем и не редактируем — переносим ровно то, что в документе.

Перед началом прочитай `config.md` (кабинет, категории, сегменты, образцы).
Если в нём остались пустые поля `<…>` — спроси у пользователя, не угадывай.

## Жёсткие запреты

- НЕ отправлять, НЕ активировать, НЕ планировать рассылки. Финал работы — сохранённый черновик.
- НЕ удалять ничего (рассылки, сегменты, файлы, пользователей).
- Работать только в разделе «Рассылки» (и в файловом хранилище для баннеров). Не заходить в базу пользователей, настройки аккаунта, права.
- НЕ менять рассылки, которые уже запланированы или отправлены. Если черновик с такой темой уже есть — обновить его, а не создавать дубль (спросить, если сомнения).
- НЕ запрашивать и НЕ вводить пароль. Пользователь сам залогинен в GetCourse в Chrome.
- НЕ переписывать, не «улучшать», не сокращать текст. Опечатки — списком в отчёте, без правок.
- Получатели: НЕ менять — оставлять сегмент/условия, скопированные из образца (пользователь правит их сам). Не ставить «Никому».
- Если чего-то не хватает или неясно — остановиться и спросить.

## Инструменты

- **Google Docs** — читать через Google Drive коннектор (`read_file_content` по id документа). Если недоступен — публичный экспорт `https://docs.google.com/document/d/<ID>/export?format=html` через WebFetch.
- **GetCourse** — через Claude in Chrome (`mcp__claude-in-chrome__*`), в уже открытой залогиненной вкладке. Во время работы пользователь вкладку не трогает.

## Шаг 1. Разбор документа

Формат документа — `doc-template.md` (вкладки «Емейл» и «Бот», шапки писем `DD/MM HH:MM … Сегмент: …`).
Читать с `includeComments: true`. Документ длинный — сохранить текст в scratchpad и работать с файлом.

Пользователь называет, КАКИЕ письма переносить (по дате/названию: «письмо 15/10», «дожим 20/10»).
Если не назвал — показать список писем из документа и спросить. Всю цепочку разом не переносить.

Из каждого письма выделить: дату/время, назначение, описание сегмента, тему, прехедер, текст для баннера,
текст письма, кнопки (подпись + ссылка), таблицы, комментарии-указания.

- Ссылки Google Docs обёрнуты в `https://www.google.com/url?q=<настоящий адрес>&sa=…` — извлечь настоящий адрес (`q`, URL-decode).
- UTM-метки ставит автор. Ссылки переносить **как есть**, ничего не добавлять. Если у ссылки нет `utm_` — отметить в отчёте, но не дописывать.
- **Картинки и дату ставит пользователь сам** (см. `config.md`). Ссылки в кнопках и сегмент из образца — сохранять, не удалять.
- Текст после «Для картинки» в письмо не вставлять — перечислить в отчёте как подпись для баннера.
- `{first_name}` оставлять как есть — GC его понимает.
- Комментарии в письмо не идут; указания по оформлению из комментариев — списком в отчёт.

**Показать пользователю таблицу разбора** (письмо → канал → тема → прехедер → кнопки/ссылки → чего не хватает) и дождаться «да» перед созданием черновиков.

## Шаг 2. Сборка

### E-mail
- В Life Practic письма собраны в **блочном конструкторе GC** (см. `config.md`). Свою HTML-вёрстку не делать — заполнять блоки копии образца.
- Каждая кнопка из документа = отдельный блок `part-mailing-button`. Стиль кнопок не менять.
- Жирный/курсив/списки переносить средствами текстового блока.
- Типографика: неразрывные пробелы после предлогов/союзов и перед тире (`&nbsp;`), кавычки «ёлочки», тире «—».
- Баннер — публичная ссылка из файлового хранилища GC.

### Telegram
- Без HTML-вёрстки. Жирный/курсив/ссылки — только то, что поддерживает редактор GC для Telegram.
- Кнопка — штатная кнопка-ссылка GC, если есть; иначе ссылка в тексте.
- Длина: текст с картинкой ≤ 1024 символа, без картинки ≤ 4096. Если длиннее — не резать, сообщить.

### ВКонтакте / MAX
- Простой текст + ссылки, без разметки. Эмодзи — только если они есть в документе.

## Шаг 3. Создание черновика в GC

1. Открыть образец нужного канала из `config.md` и нажать **«Копировать»** (так сохраняются отправитель, бот, категория, теги, подвал и стили). Пустую рассылку с нуля не создавать.
   Название задаётся прямо в окне копирования. Сразу после копирования: расписание «При вызове из процесса или формы» (`from_mission`) (сбросить старую дату), получателей не трогать, сохранить.
   В копии e-mail заменить содержимое блоков баннера, текста и кнопок; лишние блоки кнопок удалить, недостающие добавить копированием соседнего блока.
2. **Категория обязательна** — без неё рассылка не сохраняется.
3. Заполнить тему, прехедер, отправителя (из `config.md`), текст/HTML.
   **E-mail: в поле «HEAD письма» (`Mailing[headHtml]`) всегда добавлять `<vk-snippet-end/>`** — тогда в превью почтовика показывается только прехедер, без начала текста письма. Если в поле уже что-то есть — дописать с новой строки, не затирать.
4. Получатели — как в образце, не трогать.
5. Дату НЕ ставить, расписание — «По готовности» (копия наследует старую дату — сбросить). Плановую дату из документа указать в отчёте.
6. Сохранить как черновик.

### Заполнение блоков
Пошаговый рецепт для конструктора писем (Redactor, дублирование и перестановка блоков, кнопки) — в `config.md`, раздел «Рецепт e-mail». HTML текста собирать `md2gc.py`:
`python3 -I md2gc.py <текст письма.txt> '{"T1":[1,4,true],"T2":[9,17]}' out.json` (номера строк блоков; `true` — пустая строка после приветствия).
Всё вводить через JS или `type`. Буфер обмена (Cmd+V) не использовать — он портит кириллицу.

## Шаг 4. Самопроверка

1. Прогнать **«Типограф»** GC на каждом текстовом блоке и сохранить (рецепт в `config.md`, п. 6).
2. Перезагрузить страницу и сверить с документом: тема, прехедер, порядок блоков, подписи кнопок, получатели как в образце, расписание «При вызове из процесса или формы» (`from_mission`), категория. Текст — по SHA-256 (п. 7): типограф не должен был поменять ни одного слова.
3. Запустить **«Анализ текста»** и перенести новые предупреждения в отчёт (п. 8). Стоп-слова не менять, буквы не подменять.

## Отчёт пользователю

По каждому черновику: канал, тема, ссылка на черновик в GC, плановая дата из документа (не выставлена), что осталось сделать пользователю (баннер + подпись «Для картинки», ссылки кнопок, сегмент, дата), опечатки и указания из комментариев.
Напомнить: отправить тестовое письмо себе и проверить на телефоне и компьютере. Отправку делает человек.

## Обучение

Когда пользователь поправляет агента или выясняется новая особенность интерфейса GC — дописать правило в этот файл (или в `config.md`, если это данные аккаунта) и сказать, что дописал.
