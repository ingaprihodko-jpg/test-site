# Агент по сайтам

Задача: из ТЗ получить страницу на GetCourse, на которой клиенту нечего поправлять по шрифтам, типографике и отступам.

Перед началом прочитай `palette.md` и `rules.md`. Все сообщения — по-русски.

## Жёсткие запреты

- НЕ придумывать и не улучшать текст. Только то, что в ТЗ. Опечатки и вопросы — списком в отчёт. Нет текста для блока — спросить.
- НЕ публиковать без явного «да» в этом разговоре, если для проекта в памяти не записано иное. Публикация выкатывает и чужие неопубликованные правки на странице: перед ней вывести список блоков `[id^=ltBlock]`.
- НЕ удалять и не менять чужие блоки на странице, предложения, формы и настройки аккаунта.
- НЕ вводить и не запрашивать пароли. GetCourse — только в Chrome пользователя, где уже есть вход.
- Новую страницу в GC создаёт пользователь и даёт её id или ссылку.

## Шаг 1. Разбор ТЗ

Прочитать ТЗ (Google Docs через коннектор Drive, с комментариями). Показать таблицу: блок → тексты → кнопки и ссылки → картинки → чего не хватает. **Дождаться «да».**

Уточнить, если не сказано: сайт, id страницы, цвета (по умолчанию `palette.md`), шрифт (по умолчанию Manrope), есть ли формы и какие блоки GC они открывают.

## Шаг 2. Макет

Файл `<имя>.html` в корне репозитория.

- Сразу писать по `rules.md`: весь код внутри `<div class="f5-root">`, все классы с префиксом `f5-`, одна ширина контейнера на все секции.
- Цвета — только токены из `palette.md`.
- Картинки сначала искать в `assets/images/`. Иллюстрации не должны висеть в воздухе.
- Открыть через `preview_start` с именем `f5game-site`: `http://localhost:8533/<имя>.html`.

## Шаг 3. Проверка макета

Сначала расставить неразрывные пробелы: `python3 .claude/skills/gc-site/mk_embed.py --typograph <имя>.html`. Затем запустить проверку на 375px и 1440px (см. «Как запускать проверку»). Исправить все `error` и `warn`, повторить. Посмотреть скриншоты обеих ширин самому: композицию и «висит ли картинка» скрипт не оценит.

Показать пользователю скриншоты и итог проверки. **Дождаться «да».**

## Шаг 4. Версия для GetCourse

```bash
python3 .claude/skills/gc-site/mk_embed.py <имя>.html export/<имя>-embed.html
```

Скрипт расставляет неразрывные пробелы, переводит rem в px, делает адреса картинок абсолютными, добавляет защиту от стилей GC и показывает блоки с `data-reveal`. Он сообщает, если нашёл то, что сам не исправляет.

## Шаг 5. Вставка в GC

Через `mcp__claude-in-chrome__*`. Во время работы пользователь вкладку не трогает.

Основной путь: навести на HTML-блок → найти кнопку настроек через `find`, не по координатам → боковая панель «Настройки», поле «Значение» → «Сохранить и закрыть». Если доступен только редактор кода, порядок такой: настоящий клик в поле → `cm.setValue()` → `ctrl+End`, пробел, `BackSpace` (иначе GC молча не сохранит) → «Сохранить» → «Закрыть».

- Буфер обмена портит кириллицу. Большой файл вставлять по рецепту из `rules.md`, раздел «GetCourse».
- После сохранения сверить SHA-256 содержимого с локальным файлом или найти свой маркер в `.lt-raw-html`.
- Кнопки форм: `window.ltShowModalBlock('b-xxxxx')`, код блока дать пользователю или взять из его `data-code`.

## Шаг 6. Проверка на живой странице

Обязательна: GC ломает то, что в макете было верно. Та же проверка в Chrome, на 375px и 1440px, в режиме `window.__QA_ROOT='.f5-root'`. Кнопки проверять настоящим кликом хотя бы по одной из каждого вида. Если нашлись ошибки — исправить в макете и пройти шаги 3–6 заново.

## Шаг 7. Публикация и отчёт

Показать список блоков страницы и спросить «публикуем?». Затем отчёт: ссылка, итог проверки на двух ширинах, скриншоты, что на стороне пользователя (ссылки без UTM, нет картинки, вопросы по ТЗ).

## Как запускать проверку

1. `resize_window` на нужную ширину (`mobile` или `width: 1440, height: 900`). Перезагрузить страницу, если вёрстка зависит от ширины при загрузке.
2. Пролистать страницу до конца и вернуться наверх, чтобы сработало появление при прокрутке. В скрытой панели браузера оно может не сработать: тогда замечание «скрытый текст» проверить на скриншоте.
3. Вставить содержимое `qa.js` в `javascript_tool` одним вызовом, как есть. На локальной странице проще: `(0,eval)(await (await fetch('/.claude/skills/gc-site/qa.js')).text())`. Перед ним можно задать `window.__QA_ROOT='<селектор>'`.
4. Результат — JSON: `summary`, `issues` (`level`, `rule`, `where`, `detail`), `stats`.

В конце вернуть ширину окна через пресет `desktop`.

`error` — нарушено правило, исправить обязательно. `warn` — посмотреть глазами: исправить или объяснить в отчёте, почему так задумано.

## Как агент учится

Клиент прислал новую правку, которая может повториться? В этой же сессии:
1. Записать её в `rules.md` с формулировкой клиента.
2. Если её можно измерить — добавить проверку в `qa.js`.
3. Сказать пользователю, что правило добавлено.
