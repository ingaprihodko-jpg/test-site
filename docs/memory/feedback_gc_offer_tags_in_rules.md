В условиях «Предложение» (deal_offer_id) в сегментах, блоках дашбордов и фильтрах заказов GC не выбирать все предложения списком — использовать теги, которые стоят на этих предложениях (`selected_tags:[…]`, `all_object_with_tags:true`). Пример: «Продукт | Подкасты», «Продукт | Озвучка», «product-ОЗВУЧКА 2.0».

**Why:** пользователь поправил (13.11.2026, дашборд 1711629 «ПОДКАСТ | Покупатели по тарифам и озвучка»): я перечислила ~70 предложений подкаста и ~380 озвучки по id. Список по id не подхватывает новые предложения и его трудно проверять.

Подвох: несколько тегов в ОДНОМ условии с `all_object_with_tags:true` = предложения со ВСЕМИ тегами сразу (пересечение). «Любой из тегов» — отдельные условия в andrule `mode:'or'`. Пересечение удобно для «продукт + тариф»: `selected_tags:['product-Подкасты','rate-Старт']`. На tsss теги: product-*/«Продукт | *» и rate-* (rate-Старт/Быстрый старт/Взрывной старт; rate-Начинающий/Продвинутый/Профессионал/ПРОФИ Персональный/Наставничество/Наставничество с диктором). Заказы «Заморозка» несут product-тег без rate — для «купили курс» брать product+rate.

Большое «ИЛИ» (24 пары тегов в одном user_hasdealrule) GC считал нестабильно (133→137→91) — разбить на несколько hasdeal в «ИЛИ», и сверять, что сумма блоков-разбивок = итог. Теги предложению ставить через список предложений (клик по тегам → чипы → «Сохранить»), POST `/pl/tag/set-object-tags` вручную даёт 500.

**How to apply:** сначала посмотреть теги предложений (`/pl/tag/by-object-type?asModelList=1&objectTypeId=5`, колонка «Теги» в списке предложений) и строить условие по тегу; по id — только если нужного тега нет, и сказать об этом. См. [[reference-gc-dashboard-bulk-edit]].
