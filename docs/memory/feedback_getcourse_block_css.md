Learned while fixing misaligned pricing-card columns on tsss.site (`ltBlock2242342488`, "Варианты раннего бронирования курса" — БЛОК 2 / БЛОК 3 columns not lining up).

**1. Never hardcode a column's `id="builderNNNNNN"` in custom CSS — it's regenerated on every page load.**
GetCourse's block builder assigns a fresh random numeric id to each column/`.builder-item` div on every render of the editor (and very likely on every published pageview too). A CSS rule pinned to `#builder2186492` worked in one session and silently stopped matching anything the moment the page was reloaded and got new ids (`#builder37098`).
**Why:** Confirmed by reading the live DOM twice, minutes apart, via `javascript_tool` in the user's own logged-in Chrome — same content, same block, different `builder*` ids each time.
**How to apply:** Only the outer block wrapper id (`id="ltBlockNNNNNNNNNN"`, one per placed block/section) is stable across reloads — confirmed unchanged across two full page reloads. Scope all selectors from there, and reach the right column structurally (`div.flex-column:nth-of-type(1)` / `:nth-of-type(2)`), never by the column's own id.

**2. Between item divs, GetCourse injects sibling `<style>` and `<script>` tags — this breaks `nth-child`.**
Each `.builder-item` is followed by its own `<style>` (icon visibility rules) and sometimes `<script>` tags as siblings inside the column. `nth-child(N)` counts *all* siblings regardless of tag, so it lands on the wrong element. `nth-of-type(N)` only counts siblings with the same tag name (`div`), which correctly skips the interleaved `<style>`/`<script>` and lands on the right `.builder-item`.
**How to apply:** Always use `div.builder-item:nth-of-type(N)` (or similar tag-qualified `nth-of-type`), never bare `nth-child`, when targeting items inside a GetCourse builder column.

**3. The block's own "CSS" settings field auto-prepends `#ltBlockNNNNNNNNNN ` to every selector you write.**
Pasting a selector that *already* starts with `#ltBlock2242342488 ...` into that block's CSS field produces a doubled selector (`#ltBlock2242342488 #ltBlock2242342488 ...`) once GetCourse scopes it — which can never match (would require the block nested inside itself). The fix looked complete (rule present in `document.styleSheets`, correct properties) but matched zero elements, and the visual result was silently unchanged.
**Why:** Discovered by reading `document.styleSheets` live after the user pasted the CSS and republished — the rule was there, verbatim, but doubled.
**How to apply:** When writing CSS meant for GetCourse's per-block CSS field, do **not** include that block's own `#ltBlockNNNNNNNNNN` prefix — write selectors as if already inside it (start straight from `div.flex-column...`). If unsure whether a given CSS field auto-scopes, paste a one-off test rule and check `document.styleSheets` for a doubled selector before finalizing.

**4. Workflow that actually works for diagnosing/fixing GetCourse layout bugs:**
1. The sandboxed Browser pane cannot log into the client's GetCourse admin (`valentina-krasnikova.ru`, `tsss.site/pl/cms/...` etc. require a real session) and some domains are policy-blocked outright — ask the user to open the page in **their own Chrome** (via `claude-in-chrome` tools: `list_connected_browsers` → `select_browser` → navigate the returned tab), which carries their real login cookies.
2. Use `javascript_tool` (`javascript_exec`) to inspect the live DOM: find target elements by their visible text (`createTreeWalker`/`querySelectorAll` + `.innerText`), walk up to the structural ancestor you need, and read `getBoundingClientRect()` / `getComputedStyle()` to measure the actual bug (e.g. compare item-by-item `top`/`height` between two columns to find exactly which item's height differs and by how much) before writing any CSS.
3. Test the candidate fix by injecting a temporary `<style id="claude-test-...">` tag via `javascript_exec` and re-measuring — never hand over untested CSS. Remove the test `<style>` afterward and tell the user explicitly that nothing was saved/published, since editing the live DOM of their real logged-in session could otherwise look like an unannounced change.
4. After the user pastes the real CSS into GetCourse's settings and publishes, **re-verify by reloading the tab and reading `document.styleSheets`** for the actual selector text that ended up registered — don't assume the pasted text survived unmodified position for position; GetCourse rewrites/auto-scopes some fields (see #3 above).

**5. The block's "Стиль" panel has a "Подробные настройки" (detailed settings) link that opens a fuller modal — don't assume the raw CSS-field workflow above is the only option.**
That modal has direct color pickers ("Цвет фона блока" = the block's own outer wrapper bg, "Показать контейнер" → "Цвет фона" = the inner white card/container bg) alongside the same auto-scoped CSS textarea (placeholder: "CSS styles for this block... Hover over an element to see its class"). For simple color/spacing changes, use the picker fields directly instead of writing CSS — faster and less error-prone. Reserve the CSS textarea for things pickers don't cover (pill/badge styling on a specific paragraph, shadows, border-radius tweaks).
**How to apply:** Open the block → click "Стиль" → click "Подробные настройки" to get the full modal with both the pickers and the CSS textarea side by side. The modal's own "Сохранить" button saves via `POST /pl/lite/block/save-settings?id=<blockId>` (200 = saved as draft) — this does NOT publish the page; publishing is a separate explicit action ("Опубликовать" in the page header) and needs its own confirmation.
**Example:** On ltBlock2247778039 ("[ФОРМА] запись на консультацию" form, f5game.site page id=4713500), the picker's "Цвет фона блока" already held a custom dark-navy `#1e142f` from earlier work — this was the actual real background, not admin-preview chrome, confirmed by finding it as the last (winning) matching rule for `.lt-block-wrapper` in `document.styleSheets`. Changed it to a brand-neutral light gray `#f4f4f7` (from index.html's palette) to match a client-requested lighter look, and added a `p:nth-of-type(N)` rule in the CSS textarea to turn one existing paragraph into a colored pill/badge — no new copy invented, see [[feedback_stick_to_tz_copy]].

**6. To visually split ONE GetCourse form-block's content (image + one big rich-text field + form fields) into several separate "cards" (like a reference site's stacked white cards on a colored page bg) — don't fight the drag-and-drop reorder UI, use flex `order` + paragraph hiding instead.**
The block builder's per-item drag handle (the up/down-arrow icon in each item's hover toolbar, next to clone/delete/settings) is a jQuery UI Sortable handle, not a click-to-move button. `computer` tool's `left_click_drag` did NOT register as a real drag for it (order stayed unchanged every time, confirmed via querying `.builder > .builder-item` classes before/after) — likely because it doesn't fire the continuous raw mousemove sequence jQuery UI Sortable listens for. Don't spend time retrying drag gestures on GetCourse's sortable handles.
**What works instead:** 
1. Click the item's **clone icon** (`.copy-item-handler`, leftmost in the toolbar) to duplicate the one rich-text item that holds title+body+everything.
2. In each duplicate, hide the paragraphs you don't want *in that copy* via CSS `display:none` on specific `p:nth-of-type(N)` (get exact N by listing `container.children` filtered to `p` tags and reading `.textContent` — see technique in point 2 below). Do NOT edit the rich-text content directly (risk of typos/breaking the real order-form's hidden fields); hiding via CSS is non-destructive and the original text field (used elsewhere, e.g. duplicated again later) stays intact.
3. Set the block's `.builder` container to `display:flex; flex-direction:column;` and give each top-level `.builder-item` an `order:N` matching where it should visually appear — this reorders them on screen without touching DOM order, so no drag needed at all.
4. To make each section look like its own card: give it `background:#fff; border-radius:16px; box-shadow:...; margin-bottom:24px` scoped by structural selector (`div.builder-item.part-text:nth-of-type(2)` etc, per point 1/2 above — count only `div` tags, ignore interleaved `<style>` siblings). Turn off the block's own single-card wrapper (`.block-box { background:transparent!important; box-shadow:none!important; padding:0!important; }`) so it stops painting one big white box behind everything, letting the block's own dark/purple bg (`.lt-block-wrapper`, from the "Цвет фона блока" picker — see point 5) show through the gaps between your new cards.
5. For a form's tail group (price/position + user fields + submit button + consent checkboxes) that should look like ONE card even though it's many separate `.builder-item`s: give them ALL the same `background:#fff` + shared `box-shadow` (overlapping shadows on flush-adjacent elements blend fine) and only round the top corners on the first (`.part-position`) and bottom corners on the last. **Don't use `:last-of-type` for "the last one"** — GetCourse renders extra `.part-commentField` items with class `hidden` (country-specific consent fields) AFTER the visible ones in the DOM, so `:last-of-type` rounds an invisible 0-size element instead of the actually-last-visible checkbox. Check each `.part-commentField`'s class/computed `display` first, then target the correct **visible** one by its literal `nth-of-type(N)` position (counting all `div` children of `.builder`) instead.
6. GetCourse re-renders the block (fresh random ids on every item, same ephemeral-id gotcha as point 1) after actions like clone — always re-query ids/positions live right before using them; an id captured earlier in the same session can already be stale.

**7. Тёмная форма GC (2026-10-20, tsss.site).** У формы GC на тёмном фоне всё ломается по-своему: чекбоксы согласия (`.type-checkbox label.field-label > input + span.label-value`) — input и текст display:block на разных строках, у `.label-value` margin-left:20px, текст тёмный, ссылки синие; позиция предложения `label.form-position.selected` имеет светло-жёлтый фон #ffffe0 и чёрный текст; `.row` внутри блока имеет margin −15px (карточка формы упирается в края телефона). Чинится CSS по стабильному #ltBlockID: flex на label, appearance:none у checkbox + свой квадрат, transparent у form-position, .row margin 0.

**8. (2026-11-03) Не привязывать стили к #ltBlock-id, если страницу будут копировать.** При копировании страницы GC выдаёт блокам новые ltBlock-id (data-code сохраняется), стили по id молча отваливаются. Пользователь попросил привязку к CSS-классам: поле «CSS-класс блока» во вкладке «Стиль» (blockParam[blockCssClass], через запятую), селектор `:is(.класс,#f5x)` даёт вес id. Сохранение — только настоящим кликом «Сохранить и закрыть».
